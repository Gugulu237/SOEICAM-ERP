# Sleek mobile layout audit — 10 November 2026

Reference: [SOEICAM ERP Mobile](https://sleek.design/project/UXViqxJgxPf). All 40 active screen versions were checked; no versions changed since the supplied React export.

This audit checks the actual route and its surrounding page layout, including headers, navigation, tables, dialogs and mobile gates. A component existing in the repository is not evidence that the intended screen is reachable or rendered as designed.

Active versions checked against Sleek. Actual route dispatch, enclosing shells and component structure reviewed for every screen; focused isolated checks plus selected full-view browser fixtures at 390px and 320px. Fixtures use example records and stub transport, not production transactions.

## Main corrections

- **Immobilisations:** dedicated phone register with one summary, compact asset/depreciation cards and New asset action; full register, history, funding and depreciation controls remain in secondary tools.
- **Équipe et profil:** direct Team-to-profile navigation, coherent contact/status card, actual monthly targets and commission estimates, and the existing employee editor.
- **Achats:** reference header, supplier debt/order/advance summary, four module buttons, compact order status/total rows and primary action.
- **Other routes:** removed legacy page shells above accounting, sales, customers and production; corrected alias routes and role-specific entry points.

## Differences that remain

These are not marked as exact synchronization. The table records the remaining differences for every screen. The most material are:

- Sales register rows cannot display product photos, exact sale times or per-row due dates that the register read model does not return. Verified cash-handover details are not invented on receipts.
- Expense, supplier settlement, receiving and payroll screens retain their existing checked workflows. A unified unpaid/bank expense writer, direct advance allocation, or receiving without an approved order is not added by a visual update.
- Commercial customer views retain their permitted data scope; invoice/debt figures absent from that scope remain unavailable. Map summaries use actual configured map and customer data.
- Sign-in and recovery stay with the configured provider. More uses real role permissions and device settings; illustrative per-topic notification switches and password-change behavior are not fabricated.

## Preserved choices

- White SOEICAM theme, actual logo and one account control.
- Manual goods issuance with centralized stock; no per-product Receive/Count controls.
- Quantity adjustments remain in Accounting with existing role restrictions.
- Real records, permissions, approvals, identity verification and transaction validation take precedence over illustrative data and switches.
