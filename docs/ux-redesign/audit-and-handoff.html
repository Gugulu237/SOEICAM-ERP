Implemented changes

  • One white and YOLA-green palette across mobile and desktop; consistent borders, controls, cards, tabular amounts, focus treatment and reduced-motion support.
  • Sales entry combines customer and products into one stage, followed by review/payment. Direct numeric quantities, stock-limit feedback, expanded product search and existing retry/attribution/receipt rules remain connected to the original services.
  • Role-specific mobile destinations and grouped collapsible desktop navigation; compact mode keeps the genuine logo and accessible names. The saved permission model remains authoritative.
  • Customer Overview / Stock & Expiry / Sales tabs are directly visible. Customer history now pages all reads, handles errors, ignores stale responses and includes headquarters-billed branches. It is explicitly a delivery balance, not a verified physical shelf count.
  • Inventory overview prioritizes alerts, recovery, stock and catalogue; authorized adjustments link to Accounting. Existing centralized stock and compact product rows remain.
  • Keyboard-operable table sorting, search-reset states, form navigation guards, readable infrastructure errors, loading skeletons and French labels.

No changes to server posting rules, database schemas, authentication providers or stored employee permissions. No production records or demonstration balances were inserted.

Shared component specification

PatternSpecification and implementation rule
Brand and colorsWhite surfaces; YOLA green #1e5631; foreground #1f2a22; muted text approximately #626b65; borders #e3e7e4; selected state #eaf3eb. Use the committed SOEICAM logo, never a substitute.
Typography and moneyInter when installed, then system sans-serif; no new web-font dependency. Body 14–16 px; titles 20–28 px; labels 12–14 px with adequate contrast. Tabular financial figures; locale-aware grouping; FCFA amount suffix, with ISO XAF retained where required by existing document metadata or labels. Preserve negative signs and accounting decimals.
Spacing and surfaces4/8 px base spacing. Controls and standard cards 12 px radius; summaries may use 16 px. White bordered surfaces, restrained shadows for overlays only. Compact layouts keep primary tasks visible.
Navigation and headersRole-specific bottom navigation, 44 px minimum touch targets and safe-area spacing. Desktop groups Workspace / Operations / Finance / Reports / Management, collapsible with saved preference and accessible icon labels. One page Back control; existing route/filter/scroll history preserved.
Buttons and actionsOne green primary action. Neutral outline secondary, red only for destructive actions. Minimum 44 px touch height; clear focus ring; disabled processing state. Financial posting keeps existing duplicate-submit/retry safeguards.
Forms and quantitiesVisible labels, appropriate numeric/date/email/tel input types, 16 px phone inputs, optional +/- around direct quantity entry. Inline stock shortage includes the actual available maximum. Preserve input on API errors; warn for edited forms on in-app navigation and document unload.
Tables and listsDesktop semantic headers, native sort buttons and aria-sort; phone records show key value/status and expandable detail fields. Search, sort and pagination remain functional. Long detailed tables scroll within a bounded container.
Tabs and filtersAccessible segmented controls with white selected surfaces and green text. Customer tabs visible at the top of the profile; language labels wrap at narrow widths. No permission is granted by showing a tab.
Inventory and productsActual lazy-loaded product photos and existing stock readers. Group by product type and size. Read-only list rows; contextual management tools; alerts, lots and expiry remain sourced from existing records.
Financial reportingExplicit reporting periods, meaningful total/subtotal hierarchy and journal/source drill-downs. Distinguish revenue from receipts, recognized expenses from settlement, open bills from deposits/credits. Never hide reconciliation differences through formatting.
Dialogs, sheets and feedbackExisting accessible dialog primitives retain focus and Escape behavior. Use confirmation for irreversible/financial actions. Loading skeletons announce status; empty and no-search-result states explain the next action; technical infrastructure errors are translated to readable messages. No unnecessary motion.
Role safeguardsHôtesse has no sale entry; commercial data stays scoped; GM attribution uses the existing canChooseSeller authorization. Existing approval controls, bank privacy, source references and audit history are preserved. Removed distribution workflows are not restored.
